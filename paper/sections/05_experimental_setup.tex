\section{Experimental Setup}
\label{sec:experiments}

\subsection{Research Questions}

The key question is whether \method{} improves claim-level evidence-set F1 compared with the strongest fixed budget selected on development data. Secondary questions investigate whether expected-F1 decoding improves on count prediction, whether calibration improves selection quality, and whether selected evidence preserves verdict macro-F1 when using a shared verifier.

The claim hierarchy is made explicit in Table~\ref{tab:claim-test-map}. The primary selector claim can only be made based on the first comparison. Calibration, count prediction and verification are diagnostic tools to see why a selector does or does not work, but they all fail to help correct a negative primary evidence effect. This hierarchy was set up to prevent the awarding of whichever secondary endpoint may be favorable.

\subsection{Development and Formal Protocols}

Seeds 13, 37 and 73 are used for the development pilot. A maximum of 20 declared configurations may be evaluated using train and development data. There is no official test during this phase. If unlocked, a formal evaluation would use seeds 13, 37, 73, 101 and 137 exactly once with the frozen code, data, features, configurations and checkpoints.

The first GPU run was done with a validated 400-claim packet to test the semantic feature path and selector mechanism. It is a feasibility experiment since its candidates are members of the released judgment universe. The main development comparison repeats the selector on the same eligible claim sample after label-blind retrieval from the whole public text and train/development image corpus. Relevance judgments are only added once the rankings are locked. The formal test is not unlocked by a qrel-packet result alone.

\subsection{Baselines and Fairness}

The controlled baselines are fixed top-$k$ selection, a calibrated 0.5 probability threshold, uncalibrated expected-F1 decoding and a learned count head. The official baseline for MOCHEG is reproduced as appropriate. The published M-RAV and MEVER values are context-dependent because their candidate construction, model access and tuning conditions differ \cite{luu2027mrav,zhang2026mever}; they are not put through paired significance testing. All rerun selectors are given the same candidates, features, supervision and configuration budget.

\subsection{Metrics and Uncertainty}

The macro precision, recall and F1 are the evidence metrics used at the claim level. The secondary evidence metrics include the exact set match, the Jaccard score, the selected count, the count mean absolute error, Recall@$k$, MAP and nDCG. Brier score, negative log-likelihood and expected calibration error are measures of calibration. Macro-F1 and class-wise F1 are used to measure verdict quality.

10,000 paired bootstrap resamples are used for main selector effects. The resampling unit is the source, event or fact-check article where reliable grouping metadata are available; otherwise claims are resampled and that limitation is noted. Seed-aligned records are averaged before the main interval, and seed dispersion is reported separately. Holm correction is applied to the prespecified selector family. Verdict preservation is evaluated using a paired non-inferiority interval with margin $-0.01$.

\subsection{Development Gate}

The test only becomes available if all of the following are true: all data and software gates pass; mean \method-minus-best-fixed evidence F1 is at least $+0.015$ over the three development seeds; the effect is positive for every seed; the calibrated Brier score is not worse than the uncalibrated one; the verdict macro-F1 is not more than 0.01 below the fixed control; the matched comparisons have the same candidate and verifier artifacts; and the development table is regenerated by a clean rerun. None of the seeds are positive and the mean effect of the full-corpus selector is negative. Thus, the gate is fail-closed irrespective of secondary diagnostics and the formal-test annotations are not available.

The positive formal claim requires a mean official-test evidence-F1 effect of at least $+0.01$ with a positive 95\% paired interval, and the verdict-effect lower bound should be above $-0.01$. A gain against an arbitrarily weak fixed budget does not satisfy this rule.

\subsection{Ablations and Robustness}

Prespecified ablations remove calibration, replace exact expected-F1 with a global threshold or ratio approximation, replace set decoding with count prediction, and remove modality or duplicate-cluster features. Robustness tests involve repeated evidence, varying the width of the packets without retuning, removing each modality and corrupting the top candidates with irrelevant items. Verdict, gold-set size, source and the need for image evidence are covered under subgroup analysis. These analyses explain a primary result but cannot rescue a failed main comparison.

\subsection{Implementation and Resources}

The primary execution host is an RTX 4090 with 24~GiB device memory, 64~GiB system memory and an Intel i9 processor with around 1~TiB free storage. The parameters for feature extraction are mixed precision, frozen and cached encoders, a text batch size of 32 and an image batch size of 64. The Python package, configurations, tests, data preparation, feature builder, selector runner and PowerShell orchestration are version controlled. Raw predictions, calibration values, selected identifiers, histories, hashes and environment metadata are stored for independent recomputation.
